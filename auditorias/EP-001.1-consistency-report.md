# EP-001.1 — Consistency Report

## 1. Prisma migrate status
Al ejecutar inicialmente `npx prisma migrate status`, el resultado indicó que existía una migración no aplicada:

```
1 migration found in prisma/migrations
Following migration have not yet been applied:
20260831131700_init_product_catalog
```

Esto se debió a que el schema fue sincronizado mediante `npx prisma db push`, lo que actualiza la base de datos pero no registra la migración en la tabla `_prisma_migrations`.

## 2. Historial de migraciones
La migración `20260831131700_init_product_catalog` **no** figuraba como aplicada en el historial interno de Prisma (tabla de migraciones).

## 3. Corrección
Primero, se verificó mediante un script de validación que las tablas `Category` y `Product` existían y contenían los datos iniciales (3 categorías y 4 productos). Como la base de datos real y el archivo de migración estaban completamente sincronizados en estructura, se utilizó el siguiente comando para reconciliar el historial sin causar destrucción de datos:

```bash
npx prisma migrate resolve --applied 20260831131700_init_product_catalog
```

Esto marca la migración como aplicada exitosamente, permitiendo que futuras migraciones se apliquen con normalidad sin intentar recrear las tablas.

## 4. Categorías dinámicas
Se identificó una restricción estática que impedía categorías dinámicas en el frontend:

- En `src/types/index.ts`, la interfaz `Product` tenía un tipo union cerrado: `category: 'lomos' | 'milanesas' | 'hamburguesas' | 'combos' | 'papas';`
- Se modificó para utilizar el tipo general `string`.

Archivos revisados y modificados:
- `src/types/index.ts` -> Modificado a `category: string;`
- `src/app/page.tsx` -> Se eliminó el casteo forzado `as any` al mapear la categoría del producto, ya que ahora es dinámico y no rompe el tipo de TypeScript.

## 5. Runtime
Se confirmó en `src/app/page.tsx` que los datos comerciales (categorías y productos) provienen exclusivamente de consultas a la base de datos (mediante `getActiveProducts()` y `getCategories()`), y se inyectan correctamente a `MenuClient.tsx`. El archivo `menu.ts` no se está utilizando en el flujo normal (sólo permanece como fixture de datos de prueba).
